**No actual errors found**: `flutter analyze` is clean, all 22 tests pass, and a

## What's good (keep doing)
- **Clean layering, verified** — screens watch providers; IO and state live in
  `services/`; models are pure. The conventions in CLAUDE.md are actually
  followed, which is rarer than it sounds.
- **Safety-critical logic is isolated and tested** — the maneuver→wrist
  decision is one pure function (`models/route_maneuver.dart`), the cue logic
  is a pure class (`services/cue_scheduler.dart`), both exhaustively tested.
  Exactly what the tech plan's "Haptic Engine as the heart" demanded.
- **Platform split done right** — `directions_fetch.dart` / `places_fetch.dart`
  conditional exports with `_io`/`_web` siblings, documented in the stubs.
- Feature-first folders are self-explanatory: `app/ features/ models/
  services/ widgets/` — you can guess every folder's purpose from its name.

## True duplication (small, real)
- `profile_service.dart` lines 38-40 vs 76-78: the intensity/lead-time/rhythm
  derivation block is copy-pasted between `scoreSurvey()` and
  `profileFromLearningDifferences()`. Extract one `_tuningFor(overall)` helper —
  this is exactly the kind of pair that drifts apart silently.
- `_friendlyStatus` (io) vs `_friendly` (web) in the directions fetchers look
  similar but parse **different error shapes** (JSON status codes vs JS
  exception strings) — borderline; fine to leave.

## ⚠ Do NOT touch (look duplicated, are not)
- `directions_fetch.dart` + `_io` + `_web`, and `places_fetch.dart` + `_io` +
  `_web` — conditional-import platform pattern; deleting either sibling breaks
  that platform.
- `firebase_options.dart` — generated by flutterfire; never hand-edit.

## Architecture notes
- The tech plan's `core/` folder (shared utils + BLE protocol constants)
  doesn't exist yet — irrelevant until Phase 3 real BLE, where the 7-byte
  packet constants will want a home (`core/ble_protocol.dart`).
- `drive_screen._iconFor()` also inspects the maneuver string for left/right —
  but only to pick an *icon*, from the same string the haptic side uses, so it
  cannot contradict the buzz. Acceptable; don't add a third interpreter.
- Home favourites are still hardcoded labels (known stub, tracked in CLAUDE.md).
