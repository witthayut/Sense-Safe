# Sense&Safe — Wristband Firmware

โค้ด Arduino สำหรับสายรัดข้อมือ ESP32-C3 ทั้งสองข้าง (ซ้าย + ขวา)

> **ทำไมอยู่ในโฟลเดอร์นี้:** repo นี้ (`Sense-Safe`) เก็บทั้งแอปและ firmware ไว้ด้วยกัน
> เพราะทั้งสองฝั่งต้องตกลง **BLE packet format เดียวกัน** — อยู่ที่เดียวกันแปลว่า
> แก้ทั้งสองฝั่งใน commit เดียวได้ และ protocol จะไม่มีวันหลุดจากกัน
> firmware **ไม่เคย** อยู่ใน `lib/` (นั่นเป็นของ Dart เท่านั้น)

## ตั้งค่า Arduino IDE (ครั้งแรกครั้งเดียว)

1. **ติดตั้ง ESP32 core** — `File → Preferences → Additional boards manager URLs` ใส่:
   ```
   https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
   ```
   แล้วไป `Tools → Board → Boards Manager` ค้น **esp32** (by Espressif Systems) → Install

2. **เลือกบอร์ด** — `Tools → Board → ESP32 Arduino` → **ESP32C3 Dev Module**
   (ถ้า core เวอร์ชันใหม่มี "ESP32C3 Super Mini" ให้เลือกอันนั้นแทน)

3. **ตั้งค่าที่ต้องแก้** (สำคัญมากสำหรับบอร์ด Super Mini):
   | ตัวเลือก | ค่า | ทำไม |
   |---|---|---|
   | **USB CDC On Boot** | **Enabled** | ถ้าไม่เปิด `Serial.print()` จะไม่ออกอะไรเลยทาง USB — เป็นปัญหาที่คนติดกันมากที่สุด |
   | Flash Size | 4MB | ค่ามาตรฐานของบอร์ดนี้ |
   | Upload Speed | 921600 | ถ้า upload fail ให้ลดเหลือ 115200 |

4. **ถ้า upload ไม่ผ่านครั้งแรก** — กดปุ่ม **BOOT ค้างไว้** แล้วแตะ **RESET** หนึ่งที
   ปล่อย BOOT แล้วค่อยกด Upload (บอร์ดจะเข้าโหมด bootloader)

5. **ไลบรารีสำหรับ `max30102_test`** — `Tools → Manage Libraries...` ค้น
   **MAX3010x** → ติดตั้ง **"SparkFun MAX3010x Pulse and Proximity Sensor Library"**
   (คลาสชื่อ `MAX30105` แต่ใช้กับ MAX30102 ได้ — ชิปตระกูลเดียวกัน)
   ตอน compile จะมี warning `"I2C_BUFFER_LENGTH" redefined` จากในไลบรารีเอง ไม่ต้องสนใจ

## การต่อสาย (สำหรับ `turn_approach`)

หันบอร์ดให้ **พอร์ต USB-C ชี้ขึ้น** — ขาที่ต้องใช้ทั้งสามอยู่ฝั่งขวาติดกันหมด
(ดูรูปเต็มที่ [`../media/ESP32-mini-pinout.jpeg`](../media/ESP32-mini-pinout.jpeg))

```
                 USB-C
            ┌─────────────┐
    GPIO5   │ o         o │  5V     <- VCC   (AH024)
    GPIO6   │ o         o │  G      <- GND
    GPIO7   │ o         o │  3.3       ข้าม (มอเตอร์ห้ามต่อ — ขานี้ของเซ็นเซอร์ ดูหัวข้อถัดไป)
    GPIO8   │ o  ESP32  o │  GPIO4  <- IN / SIG
    GPIO9   │ o   C3    o │  GPIO3
    GPIO10  │ o         o │  GPIO2
    GPIO20  │ o         o │  GPIO1
    GPIO21  │ o         o │  GPIO0
            └─────────────┘
```

| ขาบน AH024 | ขาบน ESP32-C3 | ตำแหน่ง (นับจากบน ฝั่งขวา) |
|---|---|---|
| `VCC` / `+` | **5V** | ขาที่ 1 |
| `GND` / `−` | **G** | ขาที่ 2 |
| `IN` / `SIG` / `S` | **GPIO4** | ขาที่ 4 (ข้าม `3.3`) |

**ทำไมใช้ 5V ไม่ใช่ 3V3:** 5V มาจาก USB ตรง ไม่ผ่านตัวควบคุมแรงดันบนบอร์ด
มอเตอร์กินกระแสกระชากตอนออกตัว ถ้าดึงจาก 3V3 อาจทำให้บอร์ดรีเซ็ตตัวเอง
ส่วนขาสัญญาณ 3.3V ยังสั่งงานโมดูลได้ปกติเพราะ AH024 มีทรานซิสเตอร์ในตัว

### ข้อควรระวัง

- **`5V` กับ `G` อยู่ติดกัน** — ลวดฝอยเกยกันเส้นเดียว = ลัดวงจรตรงจาก USB
- **ถอด USB ก่อนต่อสายเสมอ**
- **ห้ามใช้ `GPIO8`** (LED บนบอร์ด) และ **`GPIO9`** (ปุ่ม BOOT — ถ้าถูกดึงลง
  ตอนบูต บอร์ดจะเข้าโหมดแฟลชแทนที่จะรันโปรแกรม)
- ถ้าย้ายขาสัญญาณไปที่อื่น ต้องแก้ `MOTOR_PIN` ในสเก็ตช์ด้วย

**เริ่มจากบอร์ดเดียวก่อน** — ต่อ ESP32 ตัวเดียว + มอเตอร์ตัวเดียว ให้ผ่านก่อน
แล้วค่อยทำตัวที่สอง

## การต่อสาย GY-MAX30102 (สำหรับ `max30102_test`, issue #13)

เซ็นเซอร์คุยกับบอร์ดผ่าน **I2C** = สายข้อมูล 2 เส้น (SDA / SCL) + ไฟ + กราวด์
มอเตอร์ต่อค้างไว้ได้ ไม่ชนกัน

```
                 USB-C
            ┌─────────────┐
    GPIO5   │ o         o │  5V     <- VCC   (AH024)
SDA-> GPIO6 │ o         o │  G      <- GND   (AH024 + MAX30102 ใช้ร่วมกัน)
SCL-> GPIO7 │ o         o │  3.3    <- VIN   (MAX30102)
    GPIO8   │ o  ESP32  o │  GPIO4  <- IN    (AH024)
    GPIO9   │ o   C3    o │  GPIO3
    GPIO10  │ o         o │  GPIO2
    GPIO20  │ o         o │  GPIO1
    GPIO21  │ o         o │  GPIO0
            └─────────────┘
```

| ขาบน GY-MAX30102 | ขาบน ESP32-C3 | หมายเหตุ |
|---|---|---|
| `VIN` / `VCC` | **3.3** (ฝั่งขวา ขาที่ 3) | **ห้ามใช้ 5V** — ดูด้านล่าง |
| `GND` | **G** (ฝั่งขวา ขาที่ 2) | กราวด์ร่วมกับมอเตอร์ |
| `SDA` | **GPIO6** (ฝั่งซ้าย ขาที่ 2) | |
| `SCL` | **GPIO7** (ฝั่งซ้าย ขาที่ 3) | |
| `INT` | ไม่ต้องต่อ | ถ้าจะใช้ interrupt ทีหลัง → `GPIO10` |
| `IRD` / `RD` | **ปล่อยว่าง** | ขาไดรฟ์ LED ภายนอก ไม่เกี่ยวกับเรา |
| `3V3` (บางล็อตมี) | ปล่อยว่าง | เป็นเอาต์พุตของ regulator บนโมดูล ไม่ใช่ขาจ่ายไฟเข้า |

**ทำไม GPIO6/7 ไม่ใช่ GPIO8/9 (ค่าเริ่มต้นของบอร์ด):** `GPIO8` เป็น LED และ
`GPIO9` เป็นปุ่ม BOOT — ESP32-C3 ย้าย I2C ไปขาไหนก็ได้ด้วยซอฟต์แวร์
(`Wire.begin(6, 7)`) จึงเลือกคู่ที่ไม่มีหน้าที่พิเศษ และเก็บ `GPIO0-3` ฝั่งขวาที่เป็น
ADC ไว้วัดแรงดันแบตในอนาคต **ตัดสินใจแล้ว 2026-09-08 — ทั้ง MAX30102 และ
MPU-6050 ใช้คู่นี้ร่วมกัน** (ที่อยู่ I2C ไม่ชน: MAX30102 = `0x57`, MPU-6050 = `0x68`)

**ทำไม 3.3 ไม่ใช่ 5V:** โมดูลมีตัวต้านทาน pull-up บน SDA/SCL ที่ดึงขึ้นตามไฟเลี้ยง
ถ้าจ่าย 5V สายข้อมูลจะเป็น 5V ซึ่ง **ESP32-C3 ไม่ทน 5V** (ต่างจากมอเตอร์ที่มี
ทรานซิสเตอร์คั่นให้) เซ็นเซอร์กินไฟน้อย regulator บนบอร์ดจ่ายไหวสบาย

### สิ่งที่ `max30102_test` ทำ

| ขั้น | ทดสอบ | ผ่านเมื่อ | ถ้าไม่ผ่าน |
|---|---|---|---|
| 1/4 | บอร์ดรัน | LED กะพริบ 5 ครั้ง | ดู "ตั้งค่า Arduino IDE" ข้างบน |
| 2/4 | สแกน I2C | Serial แสดง `0x57 <- MAX30102` | สแกนซ้ำทุก 3 วิ พร้อม checklist — แก้สายได้โดยไม่ต้องแฟลชใหม่ |
| 3/4 | ยืนยันตัวชิป | `part ID 0x15 — OK` + ไฟแดงจางๆ บนโมดูล | LED กะพริบถี่ = ชิปปลอม หรือ bus ไม่นิ่ง (สายยาว / กราวด์หลุด) |
| 4/4 | อ่านชีพจร | วางปลายนิ้วบนช่องเซ็นเซอร์ → `IR` พุ่งเกิน 50000, LED กะพริบตามจังหวะหัวใจ, `beat` ขึ้นใน ~5 วิ และ `win` ขึ้นใน ~5 วิ ตัวเลขสองตัวใกล้กัน | ถ้าขึ้น `(no contact)` ทั้งที่แตะอยู่ → กดเบาลง/นิ่งขึ้น หรือลด `CONTACT_THRESHOLD` |

**หน้าจอขั้น 4 (v3, 2026-09-09)** แสดงตัวประมาณชีพจร **สองตัวอิสระ** บนตัวอย่างชุดเดียวกัน
เพื่อให้เห็นว่าตำแหน่งไหนตัวไหนยังใช้ได้:

```
IR= 94210   beat= 72   win= 71  (r=0.93 ac=0.78)   amp= 1240   ← ปลายนิ้ว: ตรงกัน
IR= 31870   beat= 53   win= 70  (r=0.85 ac=0.41)   amp=  180   ← ข้อมือ: beat นับพลาด, win ยังถูก
IR= 28440   beat= --   win= --  (noisy r=0.41)     amp=   95   ← มือขยับ: ธงคุณภาพตัดทิ้ง
IR=  2140   beat= --   win= --   (no contact)                  ← ไม่แตะ: เงียบ ไม่มีเลขโผล่
```

| คอลัมน์ | คืออะไร | ที่มาของแนวคิด |
|---|---|---|
| `beat` | นับทีละจังหวะ: เกณฑ์ปรับตัว + ช่วงห้ามนับซ้ำ 250 ms + รีเซ็ตเมื่อไม่มีจังหวะ 2 วิ LED กะพริบทุกจังหวะ | Oxullo MAX30100 BeatDetector (เขียนใหม่ตามหลักการ ไม่ได้ก๊อป เพราะเป็น GPL) |
| `win` | หน้าต่าง 4 วิ: หาคาบจาก autocorrelation ของ IR ออกค่าทุก 1 วิ รับเฉพาะเมื่อ**แดงกับ IR เห็นคลื่นเดียวกัน** (`r` = Pearson ≥ 0.8) และยอดต้องมาหลังหุบจริง (`ac` ≥ 0.3) | MAX30102_by_RF (MIT) + เกณฑ์เพิ่มจากการจำลอง |
| `amp` | ความสูงยอดล่าสุดของสัญญาณหลังกรอง (หน่วย ADC) ไว้ปรับ `BEAT_*` ถ้าจะใช้ที่ข้อมือ | |

ก่อนขึ้นบอร์ด อัลกอริทึมทั้งสองถูก port ไป Python แล้วยิงสัญญาณชีพจรสังเคราะห์
20 เคส (drift การหายใจ, dicrotic notch, noise, มือขยับ, สัญญาณอ่อนแบบข้อมือ,
ไม่มีชีพจรเลย): `win` ถูกทุกเคสที่ยอมตอบ และตอบ `--` เมื่อไม่มีชีพจรจริง
ส่วน `beat` แม่นบนปลายนิ้ว แต่เพี้ยนบนสัญญาณอ่อนมาก ตามคาด
ตัวจำลองอยู่ที่ [`../firmware/tools/sim_ppg.py`](tools/sim_ppg.py) — รัน `python firmware/tools/sim_ppg.py`
หลังแก้ค่าคงที่ตัวใดก็ตาม (ต้องแก้ให้ตรงกันทั้งสองไฟล์)
**ยังไม่ได้ทดสอบบนคนจริง** — ผลบนข้อมือจริงคือหลักฐานที่ #13 ต้องการ

`WRIST_MODE 1` ที่หัวไฟล์ = ไฟ LED สว่างขึ้น 4 เท่า, ADC กว้างขึ้น, เกณฑ์แตะลดเหลือ 20000
สำหรับลองที่**ข้อมือด้านใน** (ด้านนอกที่ใส่นาฬิกามีกระดูกกับเอ็น ชิปนี้ไม่มีไฟเขียวแบบนาฬิกา
จึงอ่านตรงนั้นแทบไม่ได้)

> ขั้น 4 ใช้ **ปลายนิ้ว** ทดสอบก่อน เพราะสัญญาณชัดที่สุด การอ่านจากข้อมือจริง

## ซ้าย vs ขวา — ใช้ sketch เดียว

บอร์ดสองตัวรันโค้ดชุดเดียวกัน ต่างกันแค่บรรทัดเดียว ตอนจะแฟลชแต่ละตัวให้แก้
`config.h` (จะมีในขั้นที่ 2):

```cpp
#define WRIST_SIDE 'L'   // เปลี่ยนเป็น 'R' ก่อนแฟลชบอร์ดอีกตัว
```

**อย่าสร้างเป็นสอง sketch แยกกัน** — โค้ดจะ drift ออกจากกันแน่นอน และนี่คือ
โค้ด safety-critical ที่ตัดสินว่าข้อมือข้างไหนสั่น

**ติดสติกเกอร์ L / R บนตัวบอร์ดทันทีหลังแฟลชเสร็จ** ไม่งั้นจะแยกไม่ออกว่าตัวไหนเป็นตัวไหน

## ความเชื่อมโยงกับฝั่งแอป

ตอนนี้แอปยังใช้ BLE จำลองอยู่ที่ [`lib/services/ble_controller.dart`](../app/lib/services/ble_controller.dart)
เมธอดที่ firmware ต้องรองรับมีแค่สองตัว:

```dart
pulse(wrist, intensity: 0.0–1.0, durationMs: int)   // สั่งสั่นหนึ่งครั้ง
testVibration(wrist, intensity)                      // ปุ่ม Test บนหน้า Devices
```

`intensity` ฝั่ง Dart เป็น `0.0–1.0` → ฝั่ง firmware แปลงเป็น **PWM duty `0–255`**
(ตามที่บันทึกไว้ใน `../report/PROJECT_BRIEF.md` หัวข้อ ★★)

รูปแบบการสั่นจริงของแต่ละ cue อยู่ที่ [`lib/services/haptic_cue_player.dart`](../app/lib/services/haptic_cue_player.dart)
— `turn_approach.ino` เล่นแพตเทิร์นชุดเดียวกันนี้ให้ลองรู้สึกดูบนฮาร์ดแวร์จริง
