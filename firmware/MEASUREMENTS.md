## สิ่งที่ตัวเลขนี้ตัดสิน

### พื้น 135 = intensity 0.53 → ครึ่งล่างของสเกลตายสนิท

โค้ดฝั่งแอปที่ผลิตค่าต่ำกว่า 0.53 = สั่งสายรัดด้วยค่าที่ไม่มีใครรู้สึกได้:

| ไฟล์ | ปัญหา | ค่าที่ผลิตออกมา |
|---|---|---|
| `app/lib/services/calibration_controller.dart:57` | ระดับ 1–2 ของหน้า Test Vibration | 0.30 / 0.475 → duty 77 / 121 ❌ |
| `app/lib/services/profile_service.dart:70` | แบบประเมินแจกโปรไฟล์เงียบ เมื่อ `overall < 0.36` | ต่ำสุด 0.35 → duty 89 ❌ |
| `app/lib/services/haptic_cue_player.dart:31` | PREP ใช้ครึ่งหนึ่งของ intensity | 0.73 × 0.5 → duty 92 ❌ |
| `app/lib/services/hapu_ema.dart:30` | `minIntensity` | 0.10 → duty 26 ❌ |
| `app/lib/features/settings/settings_screen.dart:105` | สไลเดอร์เริ่มที่ 0.1 | 48% ซ้ายของสไลเดอร์ไม่ทำงาน |

### ทางแก้ที่ตัดสินใจไว้

**ให้ firmware เป็นคนแปลงค่า** ไม่ใช่แอป:

```
duty = FLOOR + intensity × (255 − FLOOR)
```

แอปส่งแค่ 0–1 ว่า "อยากให้รู้สึกแรงแค่ไหน" firmware แปลงตามความสามารถของ
มอเตอร์ตัวเอง ทำแบบนี้แล้วบั๊กทั้ง 5 แถวข้างบนหายพร้อมกัน เพราะไม่มีค่าใด
ที่แอปส่งได้อีกแล้วที่จะต่ำกว่าพื้น — และถ้าวันหลังเปลี่ยนไปใช้ LRA ตามสเปค
เดิมในรายงาน แก้ค่า `FLOOR` ที่เดียวจบ

### `FLOOR` ต้องปรับได้ ไม่ใช่ค่าตายตัว

135 คือค่าของคนคนเดียว ข้อมือเดียว ความแน่นเดียว **ห้ามถือเป็นความจริงสากล**

หน้า Test Vibration ในแอป (`calibration_controller.dart`) มีไว้เพื่อการนี้อยู่
แล้วตั้งแต่ต้น — เป้าหมายระยะยาวคือให้หน้านั้น *วัด* พื้นของผู้ใช้แต่ละคน
แล้วส่งค่าไปเก็บใน firmware ไม่ใช่ฮาร์ดโค้ด 135 ทิ้งไว้

## ชุดที่ 2 — 2026-09-08 ✅ ทดสอบและยืนยันแล้ว

รอบแรกลองใส่จริงแล้วพบสองอาการ: **เบาเกินไป** และ **สั่นสั้นเกินไป**

**ทั้งสองอาการเป็นเรื่องเดียวกัน** — มอเตอร์สั่นต้องใช้เวลา 50–100 ms กว่าจะ
หมุนถึงความเร็วเต็ม ตุ๊บ 140 ms เดิมจึงใช้เวลาเกินครึ่งไปกับการเร่ง และไม่เคย
ส่งความแรงตามที่ duty สั่งเลย **การยืดตุ๊บให้ยาวขึ้นทำให้รู้สึกแรงขึ้นทันที
โดยไม่ต้องเพิ่ม duty**

### ค่าที่ใช้จริงหลังปรับ

| ระยะ | duty | ยาว | จังหวะ |
|---|---|---|---|
| 300 ม. — PREP | 185 | 300 ms × 2 (เว้น 200) | ครั้งเดียว |
| 250 ม. | 200 | 350 ms | ทุก 4.0 วิ |
| 150 ม. | 220 | 350 ms | ทุก 2.0 วิ |
| 80 ม. | 238 | 350 ms | ทุก 1.0 วิ |
| 40 ม. | 248 | 350 ms | ทุก 0.5 วิ |
| < 20 ม. — NOW | 255 | 1500 ms | ครั้งเดียว |
| ถึงที่หมาย | 185 | 900 ms | สองข้างพร้อมกัน |

**สถานะ: ผู้ใช้ใส่ข้อมือทดสอบค่าชุดนี้ทีละด่าน (โหมด `1`–`6`) แล้วยืนยันว่าใช้ได้**
ค่าเหล่านี้จึงมาจากความรู้สึกจริง ไม่ใช่การอนุมาน

ค่าอยู่ในแอปแล้วที่ `proximity_pulser.dart` และ `haptic_cue_player.dart`
เครื่องมือปรับสดอยู่ที่ `test/turn_approach` (โหมด `t1`–`t6`)

**ยังไม่ได้ทดสอบ:** ลำดับทั้งหมดต่อกันเป็นการเข้าหาทางเลี้ยวจริง (โหมด `r`) —
ทดสอบทีละด่านบอกว่าแต่ละด่านแรงพอ แต่ยังไม่ได้บอกว่าหกด่านต่อกันแล้วอ่านออก
เป็นสัญญาณเดียวที่เร่งขึ้นหรือเปล่า

### สิ่งที่ค่าชุดนี้บอก

**พื้น 135 ไม่ใช่ระดับใช้งาน** ค่าที่ใช้จริงต่ำสุดคือ 185 — ห่างจากพื้นถึง 50
duty ยืนยันว่าเส้นที่วัดตอนนั่งนิ่งใช้ตัดสินใจออกแบบโดยตรงไม่ได้

**ช่วงบนอัดกันมาก** 220 / 238 / 248 / 255 ห่างกัน 7–18 duty ซึ่งน่าจะแยกไม่ออก
ไม่เป็นปัญหาเพราะ**ความถี่เป็นตัวสื่อสารหลัก** ความแรงเป็นแค่ตัวเสริม — ถ้า
พิสูจน์ได้ว่าแยกไม่ออกจริง ยุบเหลือ 2 ระดับได้โดยไม่เสียความหมาย
